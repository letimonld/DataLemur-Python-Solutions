## 🧠 My Approach

For each problem, I try to follow this process:

```text
1. Understand the problem
        ↓
2. Identify the input and output
        ↓
3. Think about possible approaches
        ↓
4. Choose the appropriate data structure
        ↓
5. Write the solution
        ↓
6. Test edge cases
        ↓
7. Analyze time complexity
        ↓
8. Analyze space complexity
        ↓
9. Look for optimization
```

## ⏱️ Complexity

I try to document the complexity of my solutions whenever relevant.

Example:

```python
def contains_duplicate(numbers):
    return len(numbers) != len(set(numbers))
```

Complexity:

```text
Time:  O(n)
Space: O(n)
```

Understanding complexity is especially important when working with large datasets.

## 💡 Data Engineering Perspective

For each problem, I also try to think beyond the interview question.

For example:

> "What happens if this input contains 10 million records?"

Questions I consider:

* Will the solution fit in memory?
* Can I process the data in chunks?
* Can I use a generator?
* Would a dictionary or set improve performance?
* Can the work be parallelized?
* Would SQL be better than Python for this task?
* How would this work inside an ETL pipeline?
